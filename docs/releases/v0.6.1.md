# v0.6.1 — rebuild for nginx 1.31.9 and 1.30.7 security releases

Rebuild the v0.6.0 module for **nginx mainline 1.31.9** and **nginx stable
1.30.7**, both released on 2026-11-18 to fix several nginx security issues.
There are no module or protocol changes. The module version advances because
v0.6.0 has already shipped and published tags are immutable.

## nginx security fixes

The fixes are in nginx itself, not in this module. Upgrade nginx and the module
together; a module must match the exact nginx version, libc and architecture of
its runtime.

| CVE | nginx issue | Fixed in |
| --- | --- | --- |
| CVE-2026-123007 | HTTP/2 flow control window overflow (memory corruption) | 1.31.9, 1.30.7 |
| CVE-2026-118899 | endless loop while reading the request body over SSL | 1.31.9, 1.30.7 |
| CVE-2026-113425 | use-after-free in the mail proxy server | 1.31.9, 1.30.7 |
| CVE-2026-123633 | use-after-free in HTTP/2 when `worker_connections` are exhausted | 1.31.9, 1.30.7 |
| CVE-2026-121810 | use-after-free in HTTP/3 when `worker_connections` are exhausted | 1.31.9, 1.30.7 |
| CVE-2026-123634 | use-after-free in the resolver during simultaneous lookups in subrequests | 1.31.9, 1.30.7 |
| CVE-2026-125283 | buffer overflow with `try_files` and `alias` | 1.31.9, 1.30.7 |
| CVE-2026-120967 | stream: client certificates verified against the default server instead of the SNI server | 1.31.9, 1.30.7 |
| CVE-2026-123640 | `ngx_stream_ssl_preread_module` parses malformed ClientHello differently | 1.31.9, 1.30.7 |
| CVE-2026-120993 | NULL pointer dereference with PROXY protocol v2 and dynamic certificates (1.31.4+ only) | 1.31.9 |

See the [nginx security advisories](https://nginx.org/en/security_advisories.html)
and the [1.31.9](https://nginx.org/en/CHANGES) /
[1.30.7](https://nginx.org/en/CHANGES-1.30) change logs.

nginx 1.31.9 also changes request parsing: header lines without a colon are now
rejected, and so are chunked request bodies with too much framing overhead.

Nginx **1.31.8** and **1.30.6** users who cannot upgrade yet can keep using the
signed [v0.6.0 builds](https://github.com/teian/ngx_http_pow_gate/releases/tag/v0.6.0),
but stay exposed to the issues above.

Each module includes a `.sig` signature and `.pem` certificate. `SHA256SUMS`
covers all eight modules. The release workflow requires two independent,
byte-identical builds per module and attaches GitHub build-provenance
attestations before publishing.

## Verify

Download your module, its `.sig` and `.pem`, and `SHA256SUMS`, then run:

```bash
module=ngx_http_pow_gate_module-0.6.1-nginx1.31.9-glibc-amd64.so
sha256sum -c --ignore-missing SHA256SUMS
gh attestation verify "$module" --repo teian/ngx_http_pow_gate
cosign verify-blob \
  --certificate "$module.pem" \
  --signature "$module.sig" \
  --certificate-identity 'https://github.com/teian/ngx_http_pow_gate/.github/workflows/release.yml@refs/tags/v0.6.1' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  "$module"
```
