# v0.7.0 — metrics, bundled rules & policy inputs (nginx 1.31.10)

Adds what an operator needs around the gate: counters for every outcome,
ready-made crawler rules, more inputs for the policy `map`, and clearances that
survive a restart without Redis. All of it is opt-in; an existing configuration
keeps working unchanged. Built for **nginx mainline 1.31.10** and **nginx
stable 1.30.7**.

## What changed

- **Metrics.** `pow_gate_status;` in a location serves counters per
  `(result, reason)` in the Prometheus text format, shared across workers and
  kept across a reload, plus the load gauges. See
  [Metrics](https://github.com/teian/ngx_http_pow_gate/blob/v0.7.0/docs/configuration.md#metrics).
- **Bundled rules.** [`rules/`](https://github.com/teian/ngx_http_pow_gate/tree/v0.7.0/rules) holds `map` includes for AI
  crawlers, search engines and automation tools, and verifier blocks with the
  published range feeds of Google, Bing, DuckDuckGo, Apple, OpenAI and
  Perplexity. `scripts/robots2map.py` turns a `robots.txt` into `map` entries.
  The files are in the repository at this tag, not in the release artifacts.
- **Weighted scoring.** `pow_gate_weights $a $b …;` sums integer signals into
  `$pow_gate_score`, which a `map` turns into a decision.
- **Load-adaptive difficulty.** `$pow_gate_load` (one-minute load as a
  percentage of the CPUs) and `$pow_gate_load_1m` feed
  `pow_gate_difficulty_scale $var;`, a multiplier for newly issued challenges.
  Clients that are already cleared are not challenged again when load rises.
- **Restart survival.** `pow_gate_state_file <file>;` keeps the store identity
  on disk, so clearances survive a full restart on a single instance.
  Challenges and no-JS grants issued before the restart are refused, because
  the record of which ones were already redeemed is lost with the restart.
- **Honeypot.** The embedded challenge page carries a hidden link to
  `{endpoint}trap`. A hit is answered with `404`, logged as
  `result=honeypot` with a `warn` line for fail2ban, and counted. The module
  does not block the client itself.
- **`deny:<status>`.** A decision can refuse with any status from 400 to 599;
  `deny:444` closes the connection without a response.
- **`pow_gate_cookie_partitioned on;`** adds `Partitioned` (and forces
  `Secure`) for gated content inside third-party iframes.
- **Link previews.** [`examples/link-previews.conf`](https://github.com/teian/ngx_http_pow_gate/blob/v0.7.0/examples/link-previews.conf)
  admits preview fetchers: checked against the operator's ASN where it owns its
  network, by User-Agent otherwise, and rate-limited in both cases.

New how-tos: [Use the bundled rules](https://github.com/teian/ngx_http_pow_gate/wiki/Howto-Use-the-bundled-rules),
[Keep link previews working](https://github.com/teian/ngx_http_pow_gate/wiki/Howto-Keep-link-previews-working) and
[Monitor the gate](https://github.com/teian/ngx_http_pow_gate/wiki/Howto-Monitor-the-gate).

## Upgrade notes

- **Protocol and cookies are unchanged.** Protocol v2 clients, cookie names and
  existing configurations work as before.
- **`/verify` accepts a challenge at or above the location's difficulty**
  instead of exactly equal. This is what lets a load surcharge apply to new
  challenges only. A challenge below the required difficulty is still rejected.
- **Replacing the module needs a restart**, which invalidates clearances once
  unless Redis is configured. Adding `pow_gate_state_file` takes effect from
  the next restart on: the first start creates the file, later ones restore it.
- **Do not share a state file between instances**, and prefer a service restart
  over nginx's binary-upgrade procedure while it is set. See
  [Restart survival](https://github.com/teian/ngx_http_pow_gate/blob/v0.7.0/docs/security.md#restart-survival).
- **Custom challenge pages** do not get the honeypot link automatically; see
  [challenge-page.md](https://github.com/teian/ngx_http_pow_gate/blob/v0.7.0/docs/challenge-page.md#the-honeypot-link).
- **Memory:** the counters reserve one additional 128 KiB shared-memory zone
  per instance.
- **Map regexes containing `{` or `}` must be quoted** in nginx, for example
  `"~^\d{3,}$"`. The bundled examples do this.

## Dependencies and toolchain

- `ureq` 3, `p256` 0.14, `sha2` 0.11, `hmac` 0.13, `getrandom` 0.4 and a
  refreshed lockfile. This clears five RustSec advisories in dependencies:
  RUSTSEC-2026-0204 (`crossbeam-epoch`), RUSTSEC-2026-0381 (`webpki-roots`),
  RUSTSEC-2026-0382 (`rustls-webpki`), RUSTSEC-2026-0387 (`crypto-bigint`) and
  RUSTSEC-2026-0592 (`url`). `webpki-roots` is the trust store of the HTTPS
  client that fetches crawler range feeds.
- Release modules are built with Rust 1.100. The musl build moved to Alpine
  3.24 with clang 20, the same Alpine release as the `nginx:alpine` image.
- Building from source now needs **Rust 1.88 or newer**.

A module must match the exact nginx version, libc and architecture of its
runtime.

Each module includes a `.sig` signature and `.pem` certificate. `SHA256SUMS`

byte-identical builds per module and attaches GitHub build-provenance
attestations before publishing.

## Verify

Download your module, its `.sig` and `.pem`, and `SHA256SUMS`, then run:

```bash
module=ngx_http_pow_gate_module-0.7.0-nginx1.31.10-glibc-amd64.so
sha256sum -c --ignore-missing SHA256SUMS
gh attestation verify "$module" --repo teian/ngx_http_pow_gate
cosign verify-blob \
  --certificate "$module.pem" \
  --signature "$module.sig" \
  --certificate-identity 'https://github.com/teian/ngx_http_pow_gate/.github/workflows/release.yml@refs/tags/v0.7.0' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  "$module"
```
